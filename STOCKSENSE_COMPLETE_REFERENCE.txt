SECTION 1 — SYSTEM OVERVIEW
================================================================================

StockSense is a self-improving NSE stock intelligence system running entirely on
your local machine (i5 13420-H, 16GB RAM, RTX 3050 4GB, ~250GB SSD). It chains
four AI reasoning layers, streams live reasoning into a multi-terminal dashboard,
and learns from every trading day.

PIPELINE (every 30 min, 9:15–15:30 IST, Mon–Fri):
  ALL NSE TICKERS
    → LightGBM (SHAP feature reasoning)
    → Kronos foundation model (candle-path forecast)
    → Signal combiner (weighted, dynamically adjusted)
    → SLM Qwen2.5-7B-Instruct commander (NSE context, portfolio guard, stop/target)
    → Claude Sonnet CLI (top 40 batch confirm/reject)
    → DB (signal + full 4-model reasoning chain)
    → SSE stream → React frontend (4 live terminals)

EOD JOB (15:45 IST):
  Today's signals → actual closes (yfinance) → Claude Opus CLI
  → structured learnings → DB → fed back to SLM next run

WEEKEND JOB (Saturday 9:00 AM):
  Week's signals + learnings + accuracy → Claude Opus CLI
  → regime assessment + weekly review → DB

ACCURACY TRACKER (daily 8:00 PM):
  7-day rolling accuracy per model → dynamic LightGBM/Kronos weight adjustment

ALL CLAUDE CALLS: via subprocess `claude -p "..." --model <model>` (CLI subscription)
                  NEVER via Anthropic API

SECTION 4 — DATABASE SCHEMA
================================================================================

Engine: TimescaleDB (PostgreSQL 16 extension) on port 5432

TABLES:
  stocks          — All NSE EQ equities. Primary key: ticker (VARCHAR 20)
                    Columns: ticker, name, sector, industry, exchange, active, created_at
                    ~2000 rows. Populated by nse_ticker_loader.py

  ohlcv_daily     — TimescaleDB hypertable. PRIMARY source of all price data.
                    Columns: time, ticker, open, high, low, close, volume, adj_close
                    ~150M rows (26yr × 2000 stocks × ~250 trading days)
                    Populated by fetch_historical.py (Bhavcopy) + yfinance gaps

  ohlcv_1min      — TimescaleDB hypertable. DEFERRED to Phase 2.
                    Same columns as ohlcv_daily. For Angel One SmartAPI live ticks.

  fo_daily        — F&O Bhavcopy aggregates per stock per day.
                    Columns: time, ticker, total_oi, oi_change, put_oi, call_oi, pcr
                    Populated by fetch_f_and_o.py

  portfolio       — User's held positions (Angel One demat holdings)
                    Columns: id, ticker, quantity, avg_price, buy_date, active, notes
                    CRITICAL: SLM layer reads this to block SELL signals on unowned stocks

  signals         — Every signal fired by the pipeline.
                    Columns: id, ticker, signal_type (BUY/SELL/HOLD), timeframe,
                             price_at_signal, target_price, stop_loss,
                             ml_confidence, kronos_confidence, slm_confidence,
                             claude_confidence, final_confidence,
                             status (active/hit_target/hit_stop/expired/cancelled),
                             fired_at, resolved_at, actual_close
                    The 'outcome' column referenced in accuracy_tracker.py does NOT
                    exist in the current schema — it uses 'status' instead. This is
                    a known inconsistency (see Section 9 — Known Issues).

  signal_reasoning — Full text reasoning per model per signal.
                    Columns: id, signal_id (FK), model_name (lgbm/kronos/slm/claude/combined),
                             reasoning (TEXT), raw_output (JSONB), created_at

  learnings       — EOD and weekend review learnings logged by Claude.
                    Columns: id, learning_date, learning_type (eod_review/weekly_review/
                             pattern_failure/pattern_success), ticker, signal_id,
                             title, body, tags (TEXT[]), raw_claude_output, created_at
                    Note: schema_additions.sql adds 'model_at_fault' column referenced
                    in weekend_job.py — check schema for completeness.

  model_accuracy  — Rolling accuracy records per model.
                    Columns: id, model_name, signal_type, timeframe,
                             period_start, period_end, total_signals, correct_signals,
                             accuracy, avg_confidence, created_at

  feature_importance — LightGBM feature importance after each training run.
                    Columns: id, model_version, feature_name, importance_score, recorded_at

  slm_training_pairs — Claude distillation training pairs for SLM fine-tuning.
                    Columns: id, ticker, situation_date, situation_context,
                             claude_response, created_at
                    Note: train_commander.py also references 'trade_date', 'decision',
                    'confidence', 'reasoning' columns that are NOT in the current
                    schema_additions.sql definition (see Section 9 — Known Issues).

SQL FILES:

  data/db/schema_additions.sql  — Phase 1 additions (fo_daily, slm_training_pairs).
                                   Must be applied manually after schema.sql.

models/ml/train.py                                                     [COMPLETE]
  LightGBM training on 26yr NSE data. Run manually to train the model.

  Run command: python -m models.ml.train

  What it does:
    1. Loads all OHLCV from ohlcv_daily (all tickers with >= 300 rows)
    2. Computes features via feature_engineering.compute_features()
    3. Handles class imbalance via scale_pos_weight (neg/pos ratio)
    4. TimeSeriesSplit(n_splits=5) walk-forward cross-validation
    5. Trains LGBMClassifier with early stopping on each fold
    6. Picks best fold by AUC, computes optimal threshold via F1
    7. Retrains final model on 80% of data
    8. Evaluates on held-out 20% test set
    9. Saves: models/ml/saved/lgbm_{version}.pkl
              models/ml/saved/lgbm_latest.pkl (symlink-style copy)
              models/ml/saved/lgbm_{version}_threshold.json
              models/ml/saved/lgbm_latest_threshold.json
              models/ml/saved/lgbm_{version}_meta.json
   10. Writes to model_accuracy and feature_importance DB tables

  LGBM params: num_leaves=63, lr=0.03, n_estimators=1000,
               feature_fraction=0.8, bagging_fraction=0.8,
               lambda_l1=0.1, lambda_l2=0.1, min_child_samples=50

  Expected output: Test AUC ~0.60-0.65 on first run without F&O data.
                   Improves to ~0.68-0.72 once F&O features are populated.
  Expected time:   2-3 hours on i5-13420H with 26yr data.

models/kronos/combine.py                                               [COMPLETE]
  Combines LightGBM and Kronos signals with weighted confidence.

  Default weights: LightGBM 40%, Kronos 60%
  Dynamic weights: After Day 7+, weights auto-adjust based on model_accuracy DB.

  Module-level cache: _lgbm_weight, _kronos_weight
  Updated by: refresh_weights_from_db() called hourly by scheduler.

  Disagreement case: If ML says BUY and Kronos says SELL (or vice versa),
    signal → HOLD, confidence → 0.45
    reasoning → "⚠️ Model disagreement detected..." (yellow in terminal)

  Agreement bonus: +5% confidence if both models agree on same non-HOLD signal.

  Key function:
    combine_signals(ml_result, kronos_result) -> dict
    refresh_weights_from_db()  — async, reads from model_accuracy table

    BUY neutral: stop_loss < actual_close < target_price (neither hit)

    Better logic:
      if actual_close >= target_price: status = 'hit_target'
      elif actual_close <= stop_loss: status = 'hit_stop'
      else: status = 'expired'

SECTION 11 — ARCHITECTURE DECISIONS (WHY WE BUILT IT THIS WAY)
================================================================================

1. Claude CLI, never API
   All claude calls via subprocess.run(["claude", "-p", ...])
   Zero Anthropic API cost beyond Claude Code subscription.
   Models: claude-sonnet-4-5 (intraday batch), claude-opus-4-5 (EOD/weekend)

2. SSE not WebSocket
   One-way server push is correct for signal streaming.
   Frontend never sends commands to backend. SSE is simpler and more reliable.
   Reconnect: EventSource auto-reconnects on connection drop.

3. APScheduler not Celery
   No message broker needed. Single-machine, async, IST timezone-aware.
   Celery + Redis would be overkill for this use case.

4. Unsloth for SLM fine-tuning (when we get there)
   Designed specifically for consumer GPUs (RTX 3050/4GB).
   2x faster than vanilla HuggingFace training, 60% less VRAM.
   Only viable path for local fine-tuning at this hardware spec.

5. TimescaleDB not plain PostgreSQL
   26yr of daily data for 2000 stocks = ~150M rows.
   TimescaleDB hypertable partitioning makes time-range queries 10-100x faster.
   Compression on data older than 90 days reduces storage ~60%.

6. NSE Bhavcopy primary, yfinance supplement
   Bhavcopy is the official NSE record — authoritative, free, no rate limits.
   yfinance is used ONLY to fill gaps > 5 days.
   F&O Bhavcopy adds institutional-grade signal features unavailable in yfinance.

7. TradingView Lightweight Charts (deferred Phase 2)
   Free, open-source, same visual quality as Angel One's charts.
   Full TradingView widget requires paid plan for custom data.

8. All 26 years for model training
   Kronos and LightGBM need regime diversity:
   2008 Lehman crash, 2016 demonetization, 2018 IL&FS, 2020 COVID.
   A model trained only on 2020-2026 would never learn crisis behavior.

9. Portfolio guard in SLM layer
   SELL signals on unowned stocks are silently converted to SKIP.
   This prevents nonsensical recommendations and wastes no Claude API calls.

10. Pure pandas/numpy indicators
    The 'ta' library fails to build on Python 3.11 (C extension issues).
    All 41 indicators reimplemented as pure Python functions.
    No external indicator library dependency.
